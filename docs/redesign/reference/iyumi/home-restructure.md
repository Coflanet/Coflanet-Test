# 홈 화면 구조 재설계 — 결정 기록

> 2026-06-12. 홈 3열 빠른 액세스 정리 + 바텀네비 4탭 전환 + "내가 담은 이유식" 도입.

## 1. 바텀네비: 3탭 → 4탭 (홈 / 식재료 / 기록 / 마이)

**결정: 옵션A (4탭, 도입 기록을 탭으로 승격)**

| 옵션 | 내용 | 판단 |
|---|---|---|
| A | 홈/식재료/기록/마이 4탭 | ✅ 채택 |
| B | 홈/기록/마이 3탭, 식재료는 홈에서 | ✗ 식재료 DB는 차별화 핵심 — 1탭 거리 유지 필요 |
| C | 3탭 유지, 기록은 홈 바로가기 | ✗ 가장 자주 쓰는 기능이 2탭 거리 |

근거:
- VOC 1순위가 **입력 동선 최소화**(voc-analysis.md §2 — "입력 동선이 길다(터치 과다)" 빈도 높음, P0). 도입 기록은 매일 여러 번 쓰는 최빈 기능이라 어디서든 1탭 거리에 있어야 한다.
- 식재료 DB(시기별 가이드·알레르기 정보)는 이유미의 차별화 핵심이라 탭 유지.
- 4탭은 모바일 표준 범위(3~5탭) 안 — 인지 부하 증가 없음.

구현: `MainShellView` 4탭(IndexedStack 상주), `MainShellController.goHistory()`,
`/history` 라우트 제거(모든 내부 진입점이 탭 전환으로 대체 — 라우트 push 와
탭 상주 컨트롤러의 이중 바인딩 충돌 방지).

## 2. 홈 3열 빠른 액세스 제거

기존: 식재료 찾기 / 도입 기록 / 조리 타이머.

- **식재료 찾기** — 바텀네비 식재료 탭과 완전 중복 → 제거.
- **도입 기록** — 탭으로 승격(§1) → 제거.
- **조리 타이머** — 재료·레시피 맥락 없는 단독 타이머는 의미가 약하고,
  레시피 스텝 화면의 **인라인 타이머**가 실제 사용 맥락을 전부 흡수 → 제거.
  (독립 타이머 화면 `/timer` 라우트는 마이 탭 빠른 메뉴에 유지 — 회귀 경로.)

대체: 같은 자리에 **"내가 담은 이유식"** 섹션(§3) — 바로가기가 아니라
사용자가 능동적으로 관리하는 콘텐츠가 홈의 첫 행동 지점이 된다.

## 3. "내가 담은 이유식" (레시피 담기)

- `SavedRecipesService` — 담은 레시피 id 를 로컬(get_storage) 영속.
  레시피 시드는 불변 모델이라 `isFavorite` 필드 대신 서비스가 상태 보유.
- 담기 진입점: 레시피 카드(목록·홈 추천)의 ♡ 토글 + 레시피 상세 앱바 ♡.
- 홈 노출: 시기 요약 아래 가로 스크롤 카드. **탭하면 상세를 거치지 않고
  바로 스텝 실행** — 담아둔 레시피는 "만들 결심이 끝난" 상태라 중간 단계가
  마찰일 뿐이다. 빈 상태에는 담는 방법 안내 카피.
- 정렬: 최근 담은 순(서비스가 맨 앞 삽입).

## 4. 홈 최상단 "하루/농도/영양" 카드 — 유지

`_StageSummary` 는 `WeaningStage`(research-nutrition.md §4-1 근거)의
시기별 데이터를 보여주는 **현재 시기 요약**이다:
- 하루 = `dailyCount` (하루 이유식 횟수, 예: "2~3회")
- 농도 = `riceWaterRatio` (배죽 비율, 예: "7배죽")
- 영양 = `nutritionFocus` (핵심 영양, 예: "철분·아연")

생년월일 → 시기 자동 계산이라는 앱의 핵심 가치를 홈 진입 즉시 보여주는
카드이므로 **유지**. 개선 여지: "농도(배죽)" 용어가 초보 부모에게 어려움 —
탭하면 배죽 설명으로 연결하는 후속 과제.
