# UI 디테일 검증

바이브 코딩의 약점은 **디테일**이다. 코드는 돌아가지만 여백이 제각각이고, 회색 텍스트는 대비가 안 나오고, hover/disabled 상태가 없고, 터치 타깃이 작다. 이 스킬은 그걸 **추측이 아니라 수치로** 잡는다.

## 핵심 원칙

- **모호한 표현 금지.** "적당한 여백" → "16px", "충분한 대비" → "4.5:1 이상", "부드러운 전환" → "ease-out 250ms".
- **이미 있는 것을 재사용.** 새 색·새 간격·새 폰트 크기를 만들기 전에 기존 토큰/스케일에 맞는 값이 있는지 먼저 본다.
- **플랫폼을 구분한다.** iOS(HIG) / Android(Material) / Web 기준이 다르다. 맥락이 없으면 Web 기준으로 보고, 모바일 네이티브면 해당 플랫폼 수치를 쓴다.
- **한 화면에 강조는 하나.** 두 개를 똑같이 강하게 하면 둘 다 약해진다.

---

## 워크플로

1. **무엇을 만들었는지 파악** — 컴포넌트인지(버튼, 카드, 인풋), 화면인지(리스트, 폼, 대시보드). 플랫폼 확인.
2. **아래 7개 카테고리로 audit** — 해당하는 항목만. 각 항목은 통과/위반을 수치로 판정.
3. **위반 항목을 구체값으로 교정** — 코드를 직접 고친다. "여백 늘리세요"가 아니라 `padding: 12px → 16px`.
4. **깊은 근거가 필요하면 references/ 참조** — 아래 표만으로 부족할 때만.

판정은 단정형으로. "맥락에 따라 다를 수 있지만"으로 끝내지 않는다.

## Audit 체크리스트 — 7 카테고리

### 1. 간격·여백 (8pt 그리드)

모든 간격·크기는 **8의 배수**(4px 보조). 허용값: `4, 8, 12, 16, 24, 32, 48, 64, 96`. **금지값: 5, 7, 10, 11, 13, 15, 18, 22...**

- [ ] 모든 padding/margin/gap이 위 스케일에 들어가는가?
- [ ] **같은 계층은 같은 간격, 다른 계층은 더 큰 간격** — 제목↔본문 8px, 섹션↔섹션 24~32px. 전부 16px이면 그루핑이 깨진 것.
- [ ] 요소 간(마이크로) 4~16px / 섹션 간(매크로) 24~64px.
- [ ] 의심스러우면 **늘린다.** 부족한 여백이 아마추어처럼 보이게 한다.

### 2. 타이포그래피

| 항목 | 기준 |
|---|---|
| 크기 스케일 | 모듈러 스케일(1.25배): 12 / 16(본문) / 20 / 25 / 31 / 39 |
| 본문 행간 | 1.4~1.6 (16px → 22~26px) |
| 제목 행간 | 1.1~1.3 (클수록 좁게) |
| 한 줄 글자 수 | 영문 45~75자 / 한글 30~45자 |
| 자간 | 본문 0 / 큰 제목(24px+) -0.5~-1px / UPPERCASE +0.5~+2px |
| 두께 | 한 화면에 **3개 이하** (400/500/600/700 중) |

- [ ] 폰트 크기가 임의값(17px, 19px, 23px)이 아니라 스케일을 따르는가?
- [ ] 위계를 **크기만**이 아니라 **대비(색·두께)**로도 만드는가? 덜 중요한 건 없애지 말고 흐리게.

### 3. 색·대비 (WCAG AA)

| 대상 | 최소 대비 |
|---|---|
| 본문 텍스트 | **4.5:1** |
| 큰 텍스트(18pt+/14pt bold) | 3:1 |
| UI 요소·아이콘·테두리 | 3:1 |

- [ ] **회색 텍스트 대비를 실제로 계산했는가?** `#999`는 흰 배경에서 2.85:1 → **위반**. 본문 회색은 `#767676`(4.5:1)보다 진하게.
- [ ] **색만으로 정보 전달 금지.** 에러 = 빨강만 ❌ → 빨강 + 아이콘 + 텍스트 ✅ (색맹 대응).
- [ ] 색은 **1색 + 중성색 다수.** 채도 높은 색은 드물게, 각 색에 역할 하나.
- [ ] "회색"에 채도 0 무채색 대신 살짝 색조 섞인 회색.

### 4. 컴포넌트 상태 (인터랙티브 요소 전부)

**Default만 만들고 끝내면 안 된다. 디테일의 80%가 나머지 상태에서 갈린다.**

- [ ] **Default** — 사용 가능함이 분명한가
- [ ] **Hover/Focus** — 인터랙션 가능 신호 (웹/키보드 필수)
- [ ] **Active/Pressed** — 눌림 즉각 피드백
- [ ] **Disabled** — 왜 비활성인지 알 수 있나 (단순히 흐리게만 ❌)
- [ ] **Loading** — 1초+ 작업이면 진행 표시 필수
- [ ] 리스트/콘텐츠 영역이면 **Empty / Error** 상태도

### 5. 터치 타깃 (모바일)

| 플랫폼 | 최소 |
|---|---|
| iOS | 44×44 pt |
| Android | 48×48 dp |
| Web/WCAG | 44×44 px |

- [ ] 모든 탭 가능 요소가 최소 크기 이상인가? **시각 크기와 터치 영역은 분리 가능** — 24px 아이콘도 패딩으로 44px 확보.
- [ ] 터치 타깃 사이 **8px 이상** 간격.

### 6. 모션 (애니메이션이 있으면)

| 용도 | 값 |
|---|---|
| 호버·작은 변화 | 100~200ms |
| 일반 전환·모달 | 200~300ms (**기본 300ms**) |
| 페이지 전환 | 300~500ms |

- [ ] 들어오는 요소 = **ease-out**, 나가는 요소 = ease-in, 이동 = ease-in-out. **linear 금지**(물리적으로 부자연).
- [ ] 모든 모션이 4역할(연결성/인과성/계층/상태변화) 중 하나를 하는가? 아니면 뺀다.
- [ ] **`prefers-reduced-motion`** 대응 — 큰 이동은 fade로 대체.

### 7. 접근성 (마무리 점검, 우선순위 순)

1. **색·대비** (위 3번) — 가장 흔한 위반
2. **키보드** — Tab으로 모든 요소 도달, 포커스 인디케이터 명확(`outline:none`만 ❌, 2px+), 모달 포커스 트랩/복귀
3. **터치 타깃** (위 5번)
4. **alt / aria-label** — 아이콘 전용 버튼에 라벨, 이미지에 alt, 링크 텍스트는 맥락 없이도 이해 가능("여기 클릭" ❌)
5. **모션** (위 6번) + 깜빡임 초당 3회 이하

## 빠른 판정 예시

**예 1**
입력: `<button style="padding: 10px 22px; background:#4A90D9; color:#fff">저장</button>`
판정: padding 10/22 → 그리드 위반. hover/active/disabled 상태 없음. → `padding: 12px 24px`, hover/pressed/disabled 스타일 추가.

**예 2**
입력: 카드 안 제목·본문·메타 간격이 전부 12px
판정: 그루핑 부재. → 제목↔본문 8px, 본문↔메타 4px, 카드 내부 패딩 16px, 카드↔카드 16~24px.

**예 3**
입력: 보조 텍스트 `color:#999`
판정: 흰 배경 2.85:1 → AA 위반. → `#767676`(4.5:1) 이상으로.
