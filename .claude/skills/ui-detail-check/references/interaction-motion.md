# 인터랙션·모션

> 마이크로 인터랙션, 모션 원칙, 컴포넌트 상태
> 시간이 개입하는 모든 디자인의 결정 기준.

---

## 1. 마이크로 인터랙션 (Dan Saffer)

> 출처: Dan Saffer, *Microinteractions* (O'Reilly, 2013)

### 4단계 구조

| 단계 | 내용 |
|---|---|
| **Trigger** | 무엇이 인터랙션을 시작시키는가? |
| **Rules** | 트리거 후 무엇이 일어나는가? |
| **Feedback** | 사용자에게 어떻게 알리는가? |
| **Loops & Modes** | 반복되거나 변형되는가? |

---

### 예: 좋아요 버튼

- **Trigger**: 탭
- **Rules**: 비로그인 시 로그인 유도 / 이미 좋아요 시 취소
- **Feedback**: 색 변화, 햅틱, 카운트 증가 애니메이션
- **Loops**: 길게 누르면 다른 반응 (다중 좋아요 등)

> 토글 하나, 좋아요 한 번에도 4단계 설계가 있다. 디테일의 디테일.

## 2. 모션 디자인 원칙

### Easing (이징)

| 이징 | 사용 시점 |
|---|---|
| **Ease-out** (감속) | 들어오는 요소 — 자연스럽게 정착 |
| **Ease-in** (가속) | 나가는 요소 — 빠르게 사라짐 |
| **Ease-in-out** | 이동·변형 — 양 끝이 부드러움 |
| **Linear** | 거의 사용 안 함 (시계, 인디케이터 외) |

> Linear는 **물리적으로 부자연스럽다.** 현실의 모든 움직임은 가속·감속이 있다.

---

### Duration (지속 시간)

| 범위 | 시간 | 용도 |
|---|---|---|
| 마이크로 | 100~200ms | 호버, 작은 상태 변화 |
| 숏 | 200~300ms | 일반적 전환, 모달 등장 |
| 미디엄 | 300~500ms | 페이지 전환, 큰 변화 |
| 롱 | 500ms+ | 거의 사용 안 함 (사용자 인내심 한계) |

**가장 흔한 안전값**: **300ms**

---

### 모션의 4가지 역할

모든 모션은 *이 중 하나의 역할*을 해야 한다.

| 역할 | 설명 | 예시 |
|---|---|---|
| **연결성 (Connection)** | 두 요소가 같은 것임을 알림 | Hero animation, 공유 요소 전환 |
| **인과성 (Causality)** | 사용자 행동의 결과임을 보여줌 | 버튼 누름 → 모달 등장 |
| **계층 (Hierarchy)** | 무엇이 부모이고 자식인지 | 펼침·접힘, 스택 애니메이션 |
| **상태 변화 (State change)** | 상태가 바뀌었음을 알림 | 토글, 로딩, 완료 |

> **의미 없는 모션은 시간 낭비다.** 위 4가지 중 하나의 역할을 하지 못하는 모션은 빼는 게 낫다.

---

### Reduced Motion 대응

`prefers-reduced-motion` 미디어 쿼리를 존중한다.

- 큰 이동·변형 → fade로 대체
- 회전·바운스 → 즉시 상태 전환
- 시차(parallax) → 비활성화

> 멀미·전정 장애 사용자뿐 아니라, 일반 사용자도 *집중 모드*에서 이 설정을 켠다.

## 3. 컴포넌트의 5가지 상태

**모든 컴포넌트는 다음 5가지 상태를 *반드시* 디자인한다.**

| 상태 | 점검 |
|---|---|
| **Default** | 기본 모습. 사용 가능하다는 것이 분명한가? |
| **Hover / Focus** | 인터랙션 가능을 알리는가? (웹/키보드) |
| **Active / Pressed** | 눌렸다는 즉각적 피드백이 있는가? |
| **Disabled** | 왜 비활성인지 알 수 있는가? *단순히 흐리게만 처리하지 말 것* |
| **Loading** | 시간이 걸린다는 신호가 있는가? 결과 예측 가능한가? |

---

### + 데이터 상태 (리스트·콘텐츠 영역)

| 상태 | 점검 |
|---|---|
| **Empty** | 왜 비었는지, 무엇을 해야 채워지는지 |
| **Error** | 무엇이 잘못됐고 어떻게 복구하는지 |

> **디테일의 80%가 Default가 아닌 상태들에서 갈린다.**
> Default만 그리고 나머지를 미루면 *결국 다시 처음부터* 그리게 된다.

## 4. 터치 타깃 최소 크기

| 플랫폼 | 최소 크기 |
|---|---|
| iOS HIG | 44 × 44 pt |
| Android (Material) | 48 × 48 dp |
| WCAG AAA | 44 × 44 px |

---

### 핵심 원칙

**시각적 크기와 터치 영역은 같을 필요가 없다.**

작은 아이콘이라도 *주변 패딩으로* 터치 영역을 확보할 수 있다.

```
[ 시각: 24×24 아이콘 ]
[ 터치: 44×44 영역 (패딩 포함) ]
```

**터치 타깃 사이 간격**: 최소 **8px** 이상 권장 (오작동 방지)

## 5. 피드백 타이밍 (Doherty Threshold)

응답 속도 기준선:

| 시간 | 사용자 인식 |
|---|---|
| < 100ms | 즉각적 |
| 100~300ms | 빠름 |
| 300~1000ms | 시스템 작동 중 (피드백 필요) |
| 1~10초 | 명확한 진행 표시 필요 |
| 10초+ | 백그라운드 처리, 다른 작업 가능하게 |

---

### 지각된 속도

**진짜 속도**보다 **느껴지는 속도**가 중요하다.

| 기법 | 용도 |
|---|---|
| Skeleton UI | 콘텐츠 영역 로딩 |
| Optimistic update | 사용자 액션 즉시 반영 (서버 응답 전) |
| Progressive loading | 중요한 것부터 보여줌 |
| 인디케이터 | 1초 이상 걸리는 작업 |

**규칙**: 1초 이상 걸리는 작업에는 *반드시* 진행 표시.
