# 시각 디자인 기초

> 타이포그래피, 색채, 그리드, 여백
> *결정의 기준*. 단정형으로 사용한다.

---

## 1. 타이포그래피

### 활자 크기 위계 — 모듈러 스케일

일정한 비율로 크기를 곱해 위계를 만든다.

| 비율 | 이름 | 사용 맥락 |
|---|---|---|
| 1.125 | Major Second | 차분, 조밀한 정보 위주 |
| 1.250 | Major Third | 균형, 일반적인 웹/앱 |
| 1.333 | Perfect Fourth | 강한 위계, 마케팅 페이지 |
| 1.500 | Perfect Fifth | 극적, 랜딩 페이지 |

**모바일 기본 스케일 (1.250 비율, 16px 기준)**
- Caption: 12px
- Body: 16px (기본)
- H4: 20px
- H3: 25px
- H2: 31px
- H1: 39px

> iOS·Android는 시스템 다이내믹 타입을 따르는 것이 원칙. 절대 px보다 *상대 단위*(rem, sp)를 우선.

---

### 행간 (Line-height)

| 용도 | 배수 | 예 (16px 본문) |
|---|---|---|
| 본문 | 1.4 ~ 1.6 | 22~26px |
| 제목 | 1.1 ~ 1.3 | 큰 글자는 좁게 |
| 캡션·라벨 | 1.3 ~ 1.4 | — |

**왜**: 좁으면 다음 줄을 못 찾고, 넓으면 문단의 결속이 깨진다.

---

### 한 줄 글자 수 (Measure)

- **영문**: 45–75자
- **한글**: 30–45자 (글자 폭이 더 넓음)
- 모바일에서 더 짧아질 수밖에 없으면 *행간을 더 확보*해 보완한다.

---

### 자간 (Letter-spacing)

| 상황 | 값 |
|---|---|
| 본문 | 0 (기본값, 거의 만지지 않음) |
| 큰 제목 (24px+) | -0.5 ~ -1px (좁히면 단단해짐) |
| UPPERCASE | +0.5 ~ +2px (반드시 넓혀야 가독) |
| 버튼 라벨 | 폰트에 따라 — 시각적으로 조밀해 보이지 않게 |

---

### 폰트 두께 사용

- Regular (400) — 본문 기본
- Medium (500) — 약한 강조, 라벨
- Semibold (600) — 버튼, 카드 타이틀
- Bold (700) — 제목, 강한 강조

**규칙**: 한 화면에 두께 3개 이상 섞지 않는다. 위계가 흐려진다.

## 2. 색채

### 색 모델

**HSL/HSB를 우선 사용한다 (RGB보다)**
- H (Hue): 색상 — 0~360°
- S (Saturation): 채도
- L/B: 밝기

**왜**: 같은 색상(H)에서 채도·밝기를 조절하면 *조화로운 변형*이 만들어진다.

---

### 색의 기능적 분류

| 분류 | 역할 | 예시 |
|---|---|---|
| Primary | 브랜드·주요 행동 | 주 CTA |
| Secondary | 보조 행동 | 부 CTA |
| Neutral | 텍스트·배경·구분선 | 회색 계열 |
| Semantic | 의미 색 | Success/Warning/Error/Info |
| Surface | 카드·시트 배경 | 흰색·연회색 |

---

### 색의 단계 (Color Scale)

대부분의 디자인 시스템은 **50, 100, 200, ..., 900** 10단계를 사용한다.

| 단계 | 용도 |
|---|---|
| 50 | 가장 밝은 배경 (알림 배너 배경 등) |
| 500 | 기본 색 (버튼 등) |
| 700 | 호버·강조 |
| 900 | 가장 어두운 텍스트 위 색 |

**왜**: 디자인 토큰화가 가능해지고, 다크 모드 매핑이 쉬워진다.

---

### 명도 대비 (WCAG)

| 대상 | AA 기준 | AAA 기준 |
|---|---|---|
| 본문 텍스트 | 4.5:1 | 7:1 |
| 큰 텍스트 (18pt+ 또는 14pt 굵게) | 3:1 | 4.5:1 |
| UI 요소·아이콘 | 3:1 | — |

**도구**: Stark, Contrast (Mac), WebAIM Contrast Checker

> 회색 텍스트(#999 등)가 흰 배경 위에 있을 때 흔히 위반된다. 디자이너의 가장 흔한 실수.

---

### 색상 조합

| 방식 | 특징 |
|---|---|
| 유사색 (Analogous) | 색상환 인접 — 부드러움, 통일감 |
| 보색 (Complementary) | 정반대 — 강한 대비, 강조 |
| 삼각 배색 (Triadic) | 120° 간격 3색 — 균형 잡힌 다채로움 |
| 분할 보색 (Split Complementary) | 보색 + 인접 — 보색보다 부드러움 |

> 실무 안전 공식: **1색 + 중성색 다수**. 컬러 3개 이상은 *시스템 안에서* 사용한다.

## 3. 그리드 & 레이아웃

### 8pt 그리드 시스템

**원칙**: 모든 간격·크기를 **8의 배수**로. 4px 보조.

자주 쓰는 값: **4, 8, 12, 16, 24, 32, 48, 64, 96px**

**절대 사용하지 않음**: 5, 7, 11, 13 같은 어색한 수.

**왜**:
- @1x, @2x, @3x에서 깔끔하게 떨어진다
- 디자이너 간 결정 비용이 줄어든다
- 코드와 디자인이 같은 언어를 쓴다

---

### 컬럼 그리드

**모바일** (4 컬럼)
- 좌우 마진: 16~20px
- 거터: 16px

**태블릿** (8 컬럼)
- 좌우 마진: 24~32px
- 거터: 16~24px

**데스크탑** (12 컬럼)
- 컨테이너 폭: 1140~1280px
- 거터: 24~32px

---

### 안전 영역 (Safe Area)

**iOS**
- 상단 노치: 44~59pt
- 하단 홈 인디케이터: 34pt
- 좌우 둥근 모서리 고려

**Android**
- 상단 상태바: 24~32dp
- 하단 내비게이션 바: 48dp
- Edge-to-edge 디자인 고려

## 4. 여백 (Negative Space)

### 마이크로 vs 매크로

| 구분 | 범위 | 값 |
|---|---|---|
| 마이크로 | 요소 간 (아이콘-텍스트, 라벨-입력) | 4~16px |
| 매크로 | 섹션 간 (카드-카드, 그룹-그룹) | 24~64px |

**규칙**: 같은 계층끼리는 같은 간격, 다른 계층 사이는 더 큰 간격.

---

### 여백의 위계

```
[제목]
  ↕ 8px (제목과 본문은 한 덩어리)
[본문]
  ↕ 32px (다음 섹션과 분리)
[제목]
  ↕ 8px
[본문]
```

**잘못된 예**: 모든 간격이 16px → 사용자는 그루핑을 인지하지 못한다.
