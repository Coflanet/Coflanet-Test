# 접근성

> WCAG, 포용적 디자인
> *모든 사용자를 위한* 디자인 결정 기준.

---

## 1. WCAG 4원칙 (POUR)

| 원칙 | 의미 |
|---|---|
| **Perceivable** (인지 가능) | 모든 사용자가 정보를 *인지*할 수 있어야 |
| **Operable** (조작 가능) | 모든 사용자가 인터페이스를 *조작*할 수 있어야 |
| **Understandable** (이해 가능) | 정보와 조작이 *이해 가능*해야 |
| **Robust** (견고) | 보조 기술과 *호환*되어야 |

---

## 2. 실무 체크리스트

### 색·대비

- [ ] 본문 텍스트 명도 대비 4.5:1 이상 (WCAG AA)
- [ ] 큰 텍스트(18pt+ 또는 14pt 굵게) 3:1 이상
- [ ] UI 요소·아이콘 3:1 이상
- [ ] **색만으로** 정보를 전달하지 않는가? (색맹 고려)
  - 예: 에러를 빨간색만으로 표시 ❌ → 빨간색 + 아이콘 + 텍스트 ✅

---

### 키보드·포커스

- [ ] **Tab**으로 모든 인터랙티브 요소에 도달 가능한가?
- [ ] 포커스 인디케이터가 *명확히* 보이는가?
  - `outline: none`만 적용하지 말 것
  - 최소 2px의 명확한 외곽선 또는 명도 차이
- [ ] 포커스 순서가 *논리적*인가? (좌→우, 상→하)
- [ ] 모달이 열렸을 때 포커스가 모달 안에 갇히는가?
- [ ] 모달이 닫혔을 때 포커스가 트리거 요소로 돌아가는가?

---

### 터치

- [ ] 터치 타깃이 **44×44pt** (iOS) / **48×48dp** (Android) 이상
- [ ] 터치 타깃 사이에 **8pt 이상** 간격
- [ ] 작은 아이콘이라도 패딩으로 터치 영역 확보

---

### 텍스트

- [ ] 폰트 크기를 *200%까지 확대*해도 레이아웃이 깨지지 않는가?
- [ ] 이미지에 **alt 텍스트**가 있는가?
- [ ] 아이콘만 있는 버튼에 **aria-label** 또는 시각적 라벨이 있는가?
- [ ] 링크 텍스트가 *맥락 없이도* 이해 가능한가?
  - "여기를 클릭" ❌ → "이용약관 보기" ✅

---

### 모션

- [ ] **`prefers-reduced-motion`** 설정을 존중하는가?
- [ ] 깜빡이는 요소가 *초당 3회 이하*인가? (광민감성 발작 예방)
- [ ] 자동 재생되는 콘텐츠를 일시 정지·중지할 수 있는가?

---

### 폼

- [ ] 모든 입력 필드에 *연결된 라벨*이 있는가? (`<label for>` 또는 `aria-labelledby`)
- [ ] 에러 메시지가 *어떤 필드의 에러*인지 명확한가?
- [ ] 에러 메시지가 *어떻게 고칠 수 있는지* 알려주는가?
- [ ] 필수 필드가 *시각적으로 + 스크린리더에도* 표시되는가?

## 3. 명도 대비 빠른 참조

### 통과 가능 조합 예시 (흰 배경)

| 텍스트 색 | 대비 | 통과 |
|---|---|---|
| #000000 | 21:1 | AAA |
| #2D2D2D | 13.5:1 | AAA |
| #595959 | 7.0:1 | AAA |
| #767676 | 4.5:1 | AA (본문) |
| #949494 | 3.0:1 | AA (큰 텍스트만) |
| #B8B8B8 | 1.9:1 | ❌ |

> **#999는 흰 배경 위에서 통과하지 못한다.** (대비 2.85:1)
> 디자이너의 가장 흔한 실수.

## 4. 포용적 디자인 (Inclusive Design)

> 출처: Microsoft Inclusive Design Toolkit

### 핵심 명제

> 한 명을 위해 디자인하면 한 명이 쓰고,
> 다양성을 위해 디자인하면 모두가 쓴다.

---

### Persistent / Temporary / Situational 장애

| 장애 종류 | Persistent (영구) | Temporary (일시적) | Situational (상황적) |
|---|---|---|---|
| 시각 | 시각장애 | 백내장 수술 후 | 햇빛 아래 화면 |
| 청각 | 청각장애 | 귀 감염 | 시끄러운 카페 |
| 운동 | 한 팔 사용 | 팔 깁스 | 아이를 안고 있을 때 |
| 인지 | 학습장애 | 편두통 | 피곤할 때 |

**핵심**: 모든 사용자는 *언젠가* situational 장애를 겪는다.
접근성 디자인은 **모두를 위한 디자인**이다.

---

### 실전 예시

| 디자인 결정 | Persistent 사용자 | Situational 사용자 |
|---|---|---|
| 큰 터치 타깃 | 운동 장애 | 흔들리는 지하철 |
| 자막 | 청각장애 | 음소거 환경 |
| 높은 명도 대비 | 저시력 | 햇빛 아래 |
| 단순한 언어 | 인지·학습 장애 | 비모국어 사용자 |
| 키보드 내비게이션 | 운동 장애 | 마우스 고장 |

---

## 5. 접근성 우선순위 결정

모든 항목을 동시에 만족시키기 어렵다면, 다음 순서로 결정한다:

1. **색·대비** — 가장 흔한 위반, 영향 범위 가장 넓음
2. **키보드 접근성** — 운동 장애 + situational 장애 전체에 영향
3. **터치 타깃 크기** — 모바일 사용자 모두에게 영향
4. **alt 텍스트 / aria-label** — 스크린리더 사용자에게 결정적
5. **모션 대응** — 전정 장애 + 집중 모드 사용자
