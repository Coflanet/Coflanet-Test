# 핸드오프 · 보고 · 역할 프롬프트

위임을 어떻게 적고, 결과를 어떻게 돌려받을지에 대한 실무 규칙과 템플릿입니다.

## 보고·핸드오프 규칙

- **압축해서 올린다.** 워커는 전체 대화 로그가 아니라 **핵심만 압축한 결과**를 반환합니다.
  탐색의 본질은 방대한 입력에서 핵심 토큰을 증류하는 것입니다.
- **큰 산출물은 파일/메모리로.** 코드·보고서·데이터·시각화처럼 큰 결과는 대화로 복사해 넘기지 말고
  파일이나 공유 메모리에 저장한 뒤 **가벼운 참조(경로/ID)만** 조정자에게 넘깁니다. 매 단계 복사로
  정보가 손실·왜곡되는 "game of telephone"을 막고 토큰도 절약합니다.
- **계획은 메모리에 저장.** PM은 전략·계획을 외부 메모리에 기록해 컨텍스트가 잘려도 복구합니다.
- **동기 vs 비동기.** 현재 흔한 구조는 조정자가 한 묶음의 서브에이전트를 띄우고 **기다렸다가** 다음으로
  진행하는 동기 방식(조율 단순, 단 병목 존재). 의존이 적은 묶음끼리 병렬로 띄우는 것이 핵심.

## 위임 명세 템플릿 (PM → PL/플레이어)

```
[역할] 너는 "<섹션 이름>" 섹션을 담당하는 <PL/플레이어>다.
[목표] <답해야 할 단 하나의 질문 또는 만들 산출물>
[출력 형식] <정확한 형태. 예: 마크다운 표, 3열(항목·값·출처)>
[도구·소스] <쓸 도구와 우선순위. 피할 소스. 예: 1차 자료 우선, 콘텐츠팜 회피>
[경계] <범위 안/밖. 다른 섹션과의 분담선. 예: 2025년 데이터만>
[노력 예산] <도구 호출 상한, 하위 에이전트 수 상한>
[보고] <큰 산출물은 <경로>에 저장하고 요약 + 참조만 반환. 불확실/실패 시 명시>
```

## PL(섹션 리드) 프롬프트 골격

```
너는 "<섹션>"의 섹션 리드(PL)다. 이 섹션을 완료할 책임이 있다.
1) 섹션을 독립적 하위작업으로 나눈다(겹침 없이).
2) 각 하위작업을 플레이어에게 위의 4요소(목표/출력/도구/경계)로 위임한다.
3) 플레이어 결과를 1차 검증한다(루브릭은 verification.md).
4) 검증 통과분만 압축해 PM에게 보고한다. 미흡하면 해당 플레이어만 재실행.
노력 예산: <상한>. 중단 조건: 완료 기준 충족 시 즉시 보고.
```

## 플레이어(워커) 프롬프트 골격

```
너는 단일 태스크를 수행하는 플레이어다.
목표: <하나>. 출력: <형식>. 도구: <가이드>. 경계: <범위>.
넓게 시작해 좁혀간다(짧고 넓은 질의 → 가용한 것 평가 → 점진적 좁힘).
도구 결과마다 짧게 평가해 다음 행동을 정한다. 끝나면 핵심만 압축해 반환한다.
충분한 결과를 얻으면 더 파지 말고 즉시 종료한다.
```

## 실행 메모 (Cowork / Claude Code)

- 독립 작업은 **한 턴에 여러 Agent 호출을 함께** 보내 병렬 실행합니다.
- 타임아웃이 잦으면 병렬 대신 직렬로 돌려도 됩니다.
- 서브에이전트의 최종 메시지만 조정자에게 돌아오고 사용자에겐 안 보이므로, 조정자가 핵심을
  종합해 사용자에게 전달해야 합니다.
